## 문제
- 이전 세션에서 `/waypoint` Archive를 눌렀지만 문서가 저장되지 않음

## 원인 진단
- 대화 원문이 `SessionEnd` 훅이 실행될 때까지 `waypoints/.tmp/`(git 미추적 로컬 전용 폴더)에만 존재
- claude.ai/code 원격 웹 세션은 매번 새 컨테이너로 시작/종료되며, Archive가 `SessionEnd` 완료를 컨테이너 회수 전에 보장한다는 근거가 없음
- 결과적으로 로컬에만 있던 원문 로그가 컨테이너 회수와 함께 유실됨

## 조사
- claude-mem(thedotmack/claude-mem) 구조를 확인했으나, 로컬 영속 디스크를 전제로 설계되어 있어 컨테이너 회수 문제에 대한 해법이 되지 못함

## 해결책 (구현 완료)
- `Stop` 훅이 매 턴 대화를 git 추적되는 `waypoints/inprogress/<프로젝트>/<세션ID>.md`에 append 후 즉시 `git commit+push` (`waypoint-log: ...` 메시지로 원문 로그임을 구분)
- `SessionEnd`는 원문을 분류해 `waypoints/tags/`로 정리하고 원문 로그를 삭제하는 최종 정리(`waypoint: ...`) 역할만 담당
- orphan 복구 로직을 로컬 mtime 대신 git 커밋 이력 기반으로 변경 (fresh clone 시 mtime이 항상 '지금'이라 기존 방식은 판단 불가)
- 격리된 테스트 저장소로 Stop→SessionEnd→새 컨테이너 orphan 복구 전체 플로우 검증 완료
- README 업데이트, 4개 스크립트 컴파일 체크 완료
- 브랜치 `claude/waypoint-archive-check-skzze1`에 커밋·푸시 완료

## 미탐색 대안
claude-mem의 PostToolUse(툴 호출 단위 기록)와 PreCompact(컨텍스트 압축 전 백업) 훅 방식을 참고 아이디어로 검토했으나, 이번 구현에는 반영하지 않고 필요시 별도 작업으로 남겨둠.
