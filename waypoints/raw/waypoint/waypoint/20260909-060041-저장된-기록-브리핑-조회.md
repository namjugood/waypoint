# Waypoint 조회 스킬

이 스킬은 새로운 걸 만들지 않는다. `waypoints/INDEX.md`(태그트리)와
`waypoints/tags/` 아래에 이미 쌓인 기록을 읽어서, 사용자의 질문에 맞게
가공해서 보여주는 **하나의 조회 엔진**이다. 아래 프리셋들은 전부 같은
엔진 위에서 "어떤 질문을 던지느냐"만 다르다.

`INDEX.md`는 `프로젝트 → 대표태그(상태) → #해시태그 → 항목` 3단 구조다.
파일 하나(세션 하나)가 여러 주제를 다뤘으면, 그 파일은 관련된 **모든**
해시태그 아래에 링크로 나타난다 — 그래서 대표 태그를 몰라도 실제로
얘기했던 키워드로 찾으면 걸린다.

## 공통 절차

1. `waypoints/INDEX.md`를 읽어서 현재 프로젝트(현재 작업 디렉토리의 git
   remote 이름 또는 폴더명) 섹션을 찾는다.
2. 그 프로젝트 섹션 안의 `#해시태그` 목록을 훑어서 사용자 요청과 관련
   있어 보이는 것을 찾아, 필요한 만큼만 링크된
   `waypoints/tags/<project>/<대표태그>/*.md` 파일을 읽는다 (전부 다 읽지
   말고 관련 있어 보이는 것만 — 최신순 우선).
3. **INDEX.md의 해시태그들에서 못 찾았거나, 확실히 하고 싶으면** —
   `waypoints/tags/**/*.md`의 프론트매터 `tags:` 필드와 본문을 `Grep`으로
   직접 검색한다. INDEX.md는 빠른 1차 색인일 뿐이고, 실제 전체 태그는
   각 파일 프론트매터에 다 들어있다. Grep 결과는 매칭된 줄+주변 맥락만
   먼저 보고, 진짜 관련 있어 보이는 파일 몇 개만 골라서 전체를 연다
   (검색된 걸 다 열어보지 않는다 — 후보 추리기는 싸고, 전체 읽기가
   비싸다).
4. 그래도 안 보이거나, 요약이 뭔가 부정확/애매해 보이면 —
   `waypoints/tags/<...>/<파일>.md`의 프론트매터에 있는 `raw:` 경로
   (`waypoints/raw/...`)를 열어서 **원문 그대로** 확인한다. 요약은
   손실 압축이라 세부 뉘앙스가 빠질 수 있어서, 원문이 항상 같이
   보관돼 있다 — 필요할 때만 쓰는 최후 수단이다.
5. 아래 프리셋 중 어떤 것에 해당하는 요청인지 판단해서 그 형식으로 답한다.
   프리셋에 안 맞으면 그냥 자유롭게 관련 기록을 찾아 답해도 된다.

## 프리셋

### `/waypoint` 또는 "지금까지 뭐 했어" → 브리핑
현재 프로젝트의 최근 태그들을 훑어서 "지금까지 이 프로젝트에서 다룬 주제
목록 + 진행 상태"를 짧게 브리핑한다. 미완료(진행중/보류) 항목을 먼저,
완료 항목은 나중에 간단히.

### `/waypoint adr` 또는 "의사결정 기록 만들어줘" → ADR 생성
"여러 접근법 중 무엇을 택했고 왜 택했는지"가 담긴 waypoint 파일들을 찾아서,
표준 ADR(Architecture Decision Record) 포맷으로 정리한다:

```md
# ADR-XXX: <제목>
## 상태
<진행중/완료/보류>
## 맥락
<왜 이 결정이 필요했는지>
## 결정
<무엇을 선택했는지>
## 고려했지만 선택 안 한 대안
<has_unexplored_alt가 true인 항목의 unexplored_summary 활용>
## 결과
<지금까지 알려진 결과나 영향>
```

사용자가 원하면 이 내용을 실제 `.md` 파일(또는 docx/html — 이미 있는
docx/pptx 스킬 활용)로 저장해도 된다.

### "비슷한 거 있었어?" / "이거 예전에 겪지 않았어?" → 데자뷰 감지
지금 사용자가 겪고 있는 문제/질문의 키워드로 `waypoints/tags/` 전체
(현재 프로젝트뿐 아니라 다른 프로젝트도)를 `Grep`으로 훑어서(프론트매터
`tags:`와 본문 둘 다), 비슷한 태그나 내용의 과거 기록이 있으면 알려준다.
INDEX.md의 대표 태그/해시태그만 보고 판단하지 말 것 — 관련 있어 보이는
키워드가 다른 프로젝트의 어느 파일 본문에만 언급돼 있을 수도 있다. 있으면
"예전에 <프로젝트>에서 비슷한 걸 겪었고 이렇게 해결했다"는 식으로 요약.
없으면 없다고 솔직히 말한다(억지로 끼워 맞추지 않는다).

### "반복되는 패턴 있어?" → 템플릿 후보 추출
여러 waypoint에 걸쳐 비슷한 요청 패턴(예: "테스트 코드 짜줘"가 자주
반복)이 보이면, 그 패턴을 재사용 가능한 프롬프트 템플릿 형태로
제안한다. 패턴이 뚜렷하지 않으면 무리해서 만들지 않는다.

### "리포트/통계로 보여줘" → 생산성 리포트
태그별 항목 수, 최근 활동 시기, 진행중/완료/보류 비율 등을 집계해서
간단한 표나 목록으로 보여준다. 시각화(차트)가 필요하면 dataviz 스킬을
참고해서 artifact로 만들어도 된다.

## 원칙
- **없는 걸 지어내지 않는다.** 관련 기록이 없으면 "관련된 기록을 못
  찾았어요"라고 솔직히 답한다.
- **단계적으로 좁혀서 읽는다, 한꺼번에 다 읽지 않는다.** INDEX.md(가벼움)
  → 필요하면 Grep으로 후보 추리기(싸다) → 진짜 관련 있는 파일 몇 개만
  전체로 열기(비쌈) → 그래도 애매하면 그 파일의 `raw:` 원문(가장 비쌈,
  최후 수단). 검색된 걸 전부 열어보지 않는다.
- 이 스킬은 waypoints/ 데이터를 **읽기 전용**으로 다룬다. 기록 자체를
  수정/삭제하는 건 이 스킬의 역할이 아니다 (그건 훅이 담당).
