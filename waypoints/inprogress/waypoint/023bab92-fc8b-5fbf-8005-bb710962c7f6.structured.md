## #waypoint — waypoint 스킬 정상 작동 테스트

- `/waypoint` 스킬의 조회 체인(INDEX.md → 태그 파일 → Grep → raw 원문)을 이 세션에서 직접 실행해 검증
- INDEX.md 구조, 링크된 태그 파일 존재, 프론트매터 무결성, Grep 2차 검색, raw 원문 폴백 모두 정상 확인
- 결론: 스킬 정상 작동
- 부가로 이전 세션의 `capture_turn.py` `file_ts` 중복 버그 수정 이력(브랜치 머지 완료)을 확인

- 사용자가 매 세션마다 임시 브랜치가 생기고 자동으로 master push가 안 되는 것처럼 보이는 문제를 제기
- Claude가 두 가지를 구분: (1) waypoint 기록 자체(INDEX.md, tags/, raw/)는 이미 세션 종료 시 격리 worktree를 통해 master로 직접 push되도록 설계돼 정상 동작 중, (2) 실제 코드 작업 브랜치는 Claude Code on the web의 by-design 동작(세션마다 브랜치+PR)이라 레포 설정으로 제거 불가
- 유일한 우회는 API 호출 시 `outcome_branch` 파라미터 지정이나, 웹 UI에서는 노출되지 않음
- 사용자가 첨부한 스크린샷의 커밋 2개(`waypoint-log`, `waypoint-checkpoint`)는 Claude가 만든 게 아니라 waypoint 스킬의 Stop 훅(`capture_turn.py`)이 매 턴마다 대화 유실 방지를 위해 자동 생성한 것임을 확인
- 결론: 이 커밋들은 무시해도 되며, 세션이 정상 종료되면 SessionEnd 훅이 최종 내용을 master로 자동 반영함 — 버그 아니라 정상 설계
