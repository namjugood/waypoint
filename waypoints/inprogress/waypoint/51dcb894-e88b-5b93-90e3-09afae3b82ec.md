# Waypoint 조회 스킬

이 스킬은 새로운 걸 만들지 않는다. `waypoints/INDEX.md`(태그트리)와
`waypoints/tags/` 아래에 이미 쌓인 기록을 읽어서, 사용자의 질문에 맞게
가공해서 보여주는 **하나의 조회 엔진**이다. 아래 프리셋들은 전부 같은
엔진 위에서 "어떤 질문을 던지느냐"만 다르다.

## 공통 절차

1. `waypoints/INDEX.md`를 읽어서 현재 프로젝트(현재 작업 디렉토리의 git
   remote 이름 또는 폴더명) 섹션을 찾는다.
2. 사용자 요청과 관련된 태그를 찾아, 필요한 만큼만
   `waypoints/tags/<project>/<tag>/*.md` 파일을 읽는다 (전부 다 읽지 말고
   관련 있어 보이는 것만 — 파일이 많으면 최신순으로 우선).
3. 아래 프리셋 중 어떤 것에 해당하는 요청인지 판단해서 그 형식으로 답한다.
   프리셋에 안 맞으면 그냥 자유롭게 관련 기록을 찾아 답해도 된다.

## 프리셋

### `/waypoint` 또는 "지금까지 뭐 했어" → 브리핑
현재 프로젝트의 최근 태그들을 훑어서 "지금까지 이 프로젝트에서 다룬 주제
목록 + 진행 상태"를 짧게 브리핑한다. 미완료(진행중/보류) 항목을 먼저,
완료 항목은 나중에 간단히.

### `/waypoint adr` 또는 "의사결정 기록 만들어줘" → ADR 생성
"여러 접근법 중 무엇을 택했고 왜 택했는지"가 담긴 waypoint 파일들을 찾아서,
표준 ADR(Architecture Decision Record) 포맷으로 정리한다:

```md
# ADR-XXX: <제목>
## 상태
<진행중/완료/보류>
## 맥락
<왜 이 결정이 필요했는지>
## 결정
<무엇을 선택했는지>
## 고려했지만 선택 안 한 대안
<has_unexplored_alt가 true인 항목의 unexplored_summary 활용>
## 결과
<지금까지 알려진 결과나 영향>
```

사용자가 원하면 이 내용을 실제 `.md` 파일(또는 docx/html — 이미 있는
docx/pptx 스킬 활용)로 저장해도 된다.

### "비슷한 거 있었어?" / "이거 예전에 겪지 않았어?" → 데자뷰 감지
지금 사용자가 겪고 있는 문제/질문의 키워드로 `waypoints/tags/` 전체
(현재 프로젝트뿐 아니라 다른 프로젝트도)를 훑어서, 비슷한 태그나 내용의
과거 기록이 있으면 알려준다. 있으면 "예전에 <프로젝트>에서 비슷한 걸
겪었고 이렇게 해결했다"는 식으로 요약. 없으면 없다고 솔직히 말한다
(억지로 끼워 맞추지 않는다).

### "반복되는 패턴 있어?" → 템플릿 후보 추출
여러 waypoint에 걸쳐 비슷한 요청 패턴(예: "테스트 코드 짜줘"가 자주
반복)이 보이면, 그 패턴을 재사용 가능한 프롬프트 템플릿 형태로
제안한다. 패턴이 뚜렷하지 않으면 무리해서 만들지 않는다.

### "리포트/통계로 보여줘" → 생산성 리포트

## 정리

**원인 진단**: 이전 세션에서 Archive를 눌렀지만 `waypoints/`에 아무것도 안 쌓인 이유는, 원문 대화 기록이 `SessionEnd` 훅이 돌 때까지 `waypoints/.tmp/`(git에 안 올라가는 로컬 전용 폴더)에만 있었기 때문입니다. 원격 웹 세션은 매번 새 컨테이너로 시작하고 끝나면 컨테이너째 회수되는데, Archive가 `SessionEnd` 완료를 컨테이너 회수 전에 보장한다는 근거가 없어서 — 그 경우 로컬에만 있던 원문이 그대로 사라졌습니다.

**수정 내용** (요청하신 대로 "로컬 임시저장 → 세션 종료 시 정리"라는 계약은 유지하되, 매 턴 커밋 방식으로 durability 문제를 해결):
- `Stop` 훅이 매 턴 대화를 `waypoints/inprogress/<프로젝트>/<세션ID>.md`(git-tracked)에 append하고 바로 `git commit+push`합니다. 커밋 메시지는 `waypoint-log: ...`로 명확히 구분해서, 이게 AI 분류 전 원문 누적 로그라는 걸 한눈에 알 수 있게 했습니다.
- `SessionEnd`는 그대로 이 원문을 분류해서 `waypoints/tags/`로 정리하고 원문 로그를 삭제하는, 최종 정리(`waypoint: ...`) 역할만 담당합니다.
