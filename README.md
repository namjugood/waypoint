# Waypoint

Claude Code로 작업하다가 다룬 여러 접근법·주제가 대화가 끝나면 같이
사라지는 문제를 해결하는 보조 도구입니다. AI 자체가 아니라, AI를 더
효율적으로 쓰게 도와주는 유틸리티입니다.

## 뭘 해주나요

- 대화가 진행되는 동안 자동으로 내용을 기록합니다 (`waypoint`).
- 세션이 끝나면 AI가 그 기록을 태그별로 분류해서 정리합니다.
- 다음에 같은 프로젝트에서 새 세션을 시작하면, 아직 끝나지 않은
  작업이 있는지 자동으로 알려줍니다.
- `/waypoint` 스킬로 지금까지 쌓인 기록을 조회할 수 있습니다 (브리핑,
  ADR 생성, 비슷한 과거 사례 찾기, 반복 패턴 추출, 통계 리포트 등).

사용자는 세션을 언제 끝낼지, 어디에 저장할지 신경 쓸 필요가 없습니다 —
전부 자동으로 처리되고, 전부 이 저장소(git)에 커밋됩니다.

## 사용 방법

### 평소에는 아무것도 안 해도 됩니다
`.claude/settings.json`이 설치된 프로젝트에서 Claude Code로 평소처럼
대화하면 끝입니다. 세션이 끝나면 알아서 정리되고 커밋됩니다.

### 세션을 어떻게 끝내야 저장되나요?
저장(정리 + `INDEX.md` 갱신 + git commit/push)은 `SessionEnd` 훅이 실행될
때 일어납니다. 즉 **세션이 "정상적으로 끝났다"고 인식되어야** 합니다.
사용 환경별로 방법이 다릅니다.

- **터미널(CLI)에서 실행 중일 때**: 대화창에서 `exit`을 입력하거나
  `Ctrl+D`를 누르세요. 가장 확실하게 `SessionEnd`를 트리거합니다.
  `Ctrl+C` 강제 종료는 피하세요 (비정상 종료로 처리될 수 있습니다).
- **웹(claude.ai/code)에서 실행 중일 때**: 세션 목록에서 해당 세션을
  **Archive(보관)** 하세요. 이게 세션을 명시적으로 종료 처리하는
  방법입니다. **단순히 브라우저 탭을 닫거나 다른 페이지로 이동하는 것만으로는
  세션이 즉시 종료 처리되지 않을 수 있습니다** — 백그라운드에 세션이
  한동안 남아있다가 idle 타임아웃으로 나중에 정리될 가능성이 있습니다.
  지금 나눈 대화를 바로 저장소에 반영하고 싶다면, 탭을 닫기 전에
  Archive를 먼저 누르세요.

세션을 깔끔하게 못 끝내고 방치되더라도 데이터가 사라지지는 않습니다.
`Stop` 훅이 매 턴 임시 파일(`waypoints/.tmp/`)에 계속 append해두기 때문에,
같은 프로젝트에서 **다음 새 세션이 시작될 때** 10분 이상 방치된 임시
파일을 발견하면 그때 대신 정리·커밋해줍니다. 다만 이 경우 저장 시점이
"방금 끝낸 세션 직후"가 아니라 "다음에 다시 들어왔을 때"로 밀리므로,
바로 반영된 걸 확인하고 싶다면 위 방법으로 명시적으로 종료하는 걸
권장합니다.

### 쌓인 기록 확인하기
- **전체 현황**: `waypoints/INDEX.md`를 열어보면 프로젝트/태그별로 뭘
  다뤘는지, 진행중인지 완료인지 한눈에 보입니다.
- **특정 기록 내용**: `INDEX.md`의 링크를 따라 `waypoints/tags/...`
  아래 개별 `.md` 파일을 열면 그 작업의 요약, 결정 이유, (있다면)
  미탐색 대안까지 들어 있습니다.

### `/waypoint` 스킬로 물어보기
대화창에 아래처럼 치면 됩니다 (슬래시 명령이 아니어도, 자연어로 비슷하게
물어봐도 스킬이 알아서 인식합니다):

| 입력 예시 | 결과 |
|---|---|
| `/waypoint` 또는 "지금까지 뭐 했어?" | 이 프로젝트 진행 상황 브리핑 |
| `/waypoint adr` 또는 "이거 의사결정 기록으로 정리해줘" | ADR(의사결정 기록) 문서 생성 |
| "이거 비슷한 거 예전에 겪지 않았어?" | 과거 유사 사례 검색 |
| "반복되는 패턴 있어?" | 재사용 가능한 프롬프트 템플릿 후보 제안 |
| "이번 주 작업 리포트 보여줘" | 태그별 통계 요약 |

### 지켜볼 때 확인하면 좋은 것들
아직 실사용 검증 전이라, 당분간은 아래를 가끔 확인해보시는 걸 권장합니다:

1. **`waypoints/.debug.log` 파일이 생겼는지** — 있으면 훅 스크립트 어딘가
   에서 에러가 난 것입니다 (내용을 보면 어느 단계인지 알 수 있음).
2. **`waypoints/.tmp/` 안에 파일이 오래 남아있는지** — 세션이 정상
   종료되면 이 폴더는 비어있어야 합니다. 세션 하나가 끝났는데도 파일이
   남아있으면 `SessionEnd`가 못 돌았다는 뜻이고(비정상 종료), 다음 세션
   시작 시 자동으로 복구되는지 확인해보면 됩니다.
3. **`git log`로 자동 커밋이 잘 쌓이는지** — `waypoint: <프로젝트> / <제목>`
   형식으로 커밋이 하나씩 생기는지 봅니다.
4. **`INDEX.md`에 "미분류" 태그가 많이 보이는지** — AI 분류 호출이 실패해서
   폴백된 경우입니다. 데이터는 안전하지만, 너무 자주 보이면 분류 프롬프트나
   타임아웃(`session_end.py`)을 조정해야 할 신호입니다.
5. **(claude.ai/code 등 원격 웹 세션 사용 시) 자동 저장이 master로 바로
   가는지, 아니면 세션 전용 브랜치에 쌓이는지** — `git branch --show-current`
   로 지금 세션이 어느 브랜치에서 작업 중인지 확인하세요. 플랫폼이
   세션마다 전용 브랜치를 자동 배정한다면, `/waypoint` 자동 기록도
   master가 아니라 그 브랜치로 쌓입니다(`session_end.py`의
   `git_commit_and_push`는 PR을 만들지 않고 그냥 현재 체크아웃된 브랜치로
   push하기 때문). 이 경우 master에 반영하려면 그 브랜치를 주기적으로
   PR 병합해줘야 하며, 자동으로 병합되진 않습니다.

## 동작 원리

| 시점 | 훅 | 하는 일 |
|---|---|---|
| 세션 시작 | `SessionStart` | 임시 기록 파일 생성 + 이전 세션에서 못 끝낸 기록이 있으면 먼저 정리 |
| 매 턴 | `Stop` | 그 턴의 대화를 임시 파일에 기계적으로 append (AI 판단 없음) |
| 세션 종료 (best-effort) | `SessionEnd` | 헤드리스 `claude -p` 호출로 태그/상태 분류 → 정리된 문서로 저장 → 태그트리(`INDEX.md`) 갱신 → git commit/push |

`SessionEnd`가 확실히 실행된다는 보장이 없어서(예: 세션이 방치되다 자동
종료되는 경우), `Stop` 훅으로 계속 누적 저장해두고 **다음 `SessionStart`
때 처리 안 된 기록을 발견하면 그때 마저 정리**합니다. 이 이중 구조 덕분에
데이터가 사라지는 일은 없고, 정리되는 시점만 상황에 따라 달라집니다.

용어에 대해: 저희가 쓰는 "waypoint"는 Claude Code 기본 기능인
`/checkpoint`(파일 편집 되돌리기)와는 무관합니다. 헷갈리지 않게 이 도구
안에서는 "체크포인트" 대신 항상 "waypoint"라는 용어를 씁니다.

## 폴더 구조

```
waypoints/
  .tmp/                  # 진행 중인 세션의 임시 기록 (git에는 안 올라감)
  tags/
    <프로젝트>/<태그>/<날짜-시간>-<제목>.md
  INDEX.md               # 태그트리 — 전체 현황을 한눈에 보는 인덱스
```

## 다른 프로젝트에 설치하기

이 저장소는 그 자체로 "설치 가능한 패키지"입니다. 다만 설치 방식에 따라
**기록이 저장되는 범위(어디까지 서로 보이는가)** 가 달라지므로, 먼저
두 방식 중 뭘 원하는지 결정하고 그에 맞게 설치하세요.

핵심 원리: 기록이 저장되는 위치(`waypoints/` 폴더)는 훅 스크립트
파일(`.claude/scripts/lib_common.py`)이 **물리적으로 어디에 놓여
있는지**로 정해집니다(`PROJECT_ROOT = 스크립트 위치에서 두 단계 위`).
즉 "스크립트를 어디에 두느냐"가 곧 "기록이 어디에 쌓이느냐"를
결정합니다.

### 방식 A — 프로젝트별로 완전히 격리 (기본 권장)
각 프로젝트 저장소 안에 독립적으로 설치합니다. 프로젝트마다 서로 다른
`waypoints/` 폴더를 갖고, 서로의 기록을 전혀 볼 수 없습니다.

1. `.claude/settings.json`, `.claude/scripts/`, `.claude/skills/waypoint/`
   를 **그 프로젝트 저장소 안**으로 그대로 복사합니다.
2. 그 프로젝트에 이미 `.claude/settings.json`이 있다면 `hooks` 항목만
   병합합니다 (덮어쓰지 마세요).
3. `python3`, `git`, `claude` CLI가 해당 환경에서 실행 가능해야 합니다.
4. 이 방식으로 설치한 각 프로젝트는 자기 자신의 git 저장소에만
   커밋합니다. 프로젝트 A에서 만든 기록은 프로젝트 B의 `/waypoint`
   스킬에서 전혀 조회되지 않습니다.

**장점**: 기록이 그 프로젝트의 소스코드와 함께 같은 저장소 생명주기를
따라갑니다(클론/삭제/권한도 코드와 동일). 회사 프로젝트마다 접근 권한을
분리해야 하는 경우 특히 적합합니다.
**단점**: `/waypoint` 스킬의 "비슷한 거 예전에 겪었어?" (데자뷰 감지)
기능이 **프로젝트 경계를 넘지 못합니다.** 다른 프로젝트에서 겪은 비슷한
문제가 있어도 찾아주지 못합니다 — 애초에 그 기록 자체를 볼 수 없기
때문입니다.

### 방식 B — 여러 프로젝트를 한 곳에 중앙집중
여러 프로젝트를 넘나들며 작업하고, 그 기록을 한 군데서 검색·비교하고
싶다면 이 방식을 씁니다. 지금 이 저장소(`waypoint`)가 실제로 이 방식으로
운영되고 있습니다 — 여러 프로젝트를 다루면서도 `waypoints/tags/<프로젝트>/`
형태로 프로젝트별 태그만 나눠서 한 저장소에 모아 기록합니다.

1. 스크립트(`.claude/scripts/`, `.claude/skills/waypoint/`)는 **중앙
   저장소 하나에만** 설치하고, 그 저장소를 계속 그대로 유지합니다(이
   저장소를 옮기거나 복제하면 `PROJECT_ROOT`가 바뀌어 기록 위치도
   바뀝니다).
2. `.claude/settings.json`의 훅 설정을 **프로젝트별 설정이 아니라 사용자
   전역 설정**(Claude Code의 user-level settings)에 등록해서, 어떤
   프로젝트 디렉터리에서 세션을 시작하든 항상 이 중앙 저장소의 훅이
   실행되게 합니다.
3. 각 훅은 세션의 `cwd`(현재 작업 중인 프로젝트)에서 git remote 이름을
   읽어 `waypoints/tags/<그 프로젝트 이름>/...`로 나눠 저장하므로,
   실제 소스는 각기 다른 프로젝트여도 기록은 전부 이 중앙 저장소 하나에
   모입니다.

**장점**: `/waypoint`의 데자뷰 감지, 반복 패턴 추출, 통계 리포트가
프로젝트 경계 없이 전체 작업 이력을 대상으로 동작합니다.
**단점**: 여러 프로젝트의 작업 요약이 한 저장소(하나의 git 권한 범위)에
섞여 들어갑니다. 프로젝트별 접근 권한을 분리해야 한다면 부적합합니다.

### 어느 쪽을 선택해야 하나요
| 상황 | 추천 |
|---|---|
| 프로젝트마다 접근 권한/보안 경계를 분리해야 함 (예: 서로 다른 회사/클라이언트 프로젝트) | 방식 A |
| 개인 로컬 환경에서 여러 프로젝트를 오가며 작업하고, 과거 사례를 넘나들며 찾고 싶음 | 방식 B |
| 잘 모르겠다 / 우선 안전하게 시작하고 싶다 | 방식 A (기본값, 격리가 더 안전한 선택) |

두 방식을 섞을 수도 있습니다 (예: 격리가 필요한 프로젝트만 방식 A로
개별 설치하고, 나머지 개인 프로젝트들은 방식 B의 중앙 저장소에 모으는
것) — 다만 한 프로젝트 디렉터리에 두 방식의 훅이 동시에 걸리지 않도록
주의하세요 (중복 커밋/충돌 원인이 됩니다).

## 알려진 한계 (테스트 전 솔직한 공지)

- `SessionEnd`가 idle 타임아웃으로 인한 컨테이너 회수 시에도 확실히
  실행되는지는 공식 문서에 명시되어 있지 않습니다. 위에 설명한 안전망
  (다음 `SessionStart` 복구)이 이를 보완합니다.
- 훅 안에서 `claude -p`로 태그 분류를 호출하는 부분은 실제 다양한
  세션에서 아직 충분히 검증되지 않았습니다. 분류가 실패하면 원문을
  "미분류" 태그로 그대로 보존하도록 만들어뒀지만(데이터 유실 방지),
  실사용하면서 프롬프트나 타임아웃 값을 조정해야 할 수 있습니다.
- Claude Code 훅의 정확한 transcript 스키마는 버전에 따라 달라질 수
  있어서, 파싱 로직(`lib_common.py`)이 방어적으로 짜여 있긴 하지만
  실제 사용 중 조정이 필요할 수 있습니다.
