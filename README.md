# Waypoint

Claude Code로 작업하다가 다룬 여러 접근법·주제가 대화가 끝나면 같이 사라지는 문제를 해결하는 보조 도구입니다. AI 자체가 아니라, AI를 더 효율적으로 쓰게 도와주는 유틸리티입니다.

> 다른 사람이 쓰려면? 데이터 없는 깨끗한 시작점인 [waypoint-template](https://github.com/namjugood/waypoint-template)에서 "Use this template"으로 시작하세요.

## 뭘 해주나요

- 대화 중 자동으로 내용을 기록
- 세션이 끝나면 AI가 태그별로 분류해서 정리
- 다음 세션 시작 시, 아직 안 끝난 작업이 있으면 자동으로 알려줌
- `/waypoint` 스킬로 브리핑 · ADR 생성 · 과거 유사 사례 검색 · 통계 리포트 조회

세션 종료 시점이나 저장 위치를 사용자가 신경 쓸 필요는 없습니다 — 전부 자동으로 git에 커밋됩니다.

## 핵심 동작 요약

| | |
|---|---|
| **저장 시점** | 매 턴 즉시 (세션 종료를 기다리지 않음) |
| **저장 위치** | 저장소 **기본 브랜치**(`master`/`main`) — 지금 작업 중인 세션 브랜치가 아님 |
| **분류 시점** | 원문이 일정량(약 4,000자) 쌓일 때마다 조금씩 (체크포인트), 세션 종료 시 나머지 마저 |
| **태그 구조** | 파일 하나가 여러 주제를 다뤘으면, 관련된 **모든** 해시태그 아래 링크됨 (대표 태그 1개만이 아님) |
| **원문 보관** | 요약 후에도 안 지우고 `waypoints/raw/`에 그대로 남김 (요약은 손실 압축이라 필요시 원문 확인용) |
| **동시 저장 충돌** | 자동 재시도로 안전하게 병합 (아래 참고) |

즉 세션이 `exit`으로 끝나든, 웹에서 Archive를 누르든, 탭을 닫고 컨테이너가 회수되든 **원문 자체는 이미 git에 들어가 있습니다.** 최악의 경우도 "분류가 늦어지는 것"이지 "기록이 사라지는 것"이 아닙니다.

<details>
<summary><b>왜 이렇게 설계했는지 (자세히)</b></summary>

**왜 매 턴 즉시 저장하나**
`Stop` 훅이 그 턴의 대화를 `waypoints/inprogress/<프로젝트>/<세션ID>.md`에 append하고 즉시 커밋+push합니다(커밋 메시지 `waypoint-log: ...`, AI 분류 전 원문임을 표시). 세션 종료(`SessionEnd`)가 실행된다는 보장이 없기 때문에 — 특히 원격 웹 세션은 idle 타임아웃으로 컨테이너째 회수될 수 있음 — 원문 저장을 세션 종료에 의존하지 않게 만들었습니다. (이 저장소에서 실제로 겪은 문제였습니다: 이전 세션에서 Archive를 눌렀지만 SessionEnd 완료 전에 컨테이너가 회수되어 기록이 유실됐습니다.)

**왜 세션 브랜치가 아니라 기본 브랜치로 직접 가나**
원격 웹 세션은 세션마다 전용 브랜치가 자동 배정됩니다. 기록이 그 브랜치에만 쌓이면, 브랜치가 PR로 머지되기 전까지 다음 세션이 이 기록을 못 봅니다 — 세션 간 연속성이 핵심 가치인 도구인데 정작 그게 깨지는 셈입니다(이것도 이 저장소에서 실제로 겪었습니다). 그래서 `waypoints/` 변경만 별도의 격리된 git worktree로 꺼내서 `origin/<기본브랜치>` 기준으로 커밋+push합니다. **지금 세션의 실제 코드 변경(다른 커밋들)은 이 과정에서 전혀 건드리지 않습니다.** 기본 브랜치에서 직접 작업 중이라면(로컬 CLI 등) 격리할 이유가 없으니 그 자리에서 바로 커밋합니다.

**동시에 여러 세션이 저장하면?**
`INDEX.md`는 모든 프로젝트가 공유하는 단일 파일입니다. push가 다른 세션과 충돌하면(non-fast-forward), 로컬에 미리 계산해둔 내용을 그대로 덮어쓰지 않고 **그 시점 최신 내용을 다시 받아와서 그 위에 내 항목을 재계산해 삽입**하는 방식으로 재시도합니다(최대 5회). 두 세션이 동시에 저장해도 서로의 항목을 지우지 않습니다 — 격리된 테스트 저장소로 실제 충돌 상황을 재현해서 검증했습니다.

**정리가 늦어지면?**
`SessionEnd`가 못 돌아서 분류가 안 된 원문은 `waypoints/inprogress/`에 그대로 남습니다(직접 열어도 원문 그대로 읽을 수 있음). 같은 프로젝트에서 **다음 새 세션이 시작될 때** 자동으로 마저 정리됩니다 — 로컬 파일 수정 시각이 아니라 **그 파일의 마지막 git 커밋 시각**을 기준으로 10분 이상 새 커밋이 없으면 "죽은 세션"으로 판단합니다(원격 세션은 매번 새 컨테이너로 시작해 로컬 mtime을 못 믿기 때문). 다른 탭/세션이 지금 활성 중이면(최근 커밋 있으면) 건드리지 않습니다.

**왜 세션 전체를 한 번에 분류하지 않고 조금씩 나눠서(체크포인트) 하나**
세션이 길어지면 원문도 길어지는데, 예전엔 분류 호출에 원문 앞부분
20,000자만 넘겨서 뒷부분이 통째로 누락되는 문제가 있었습니다(고정
길이 제한은 그 길이를 넘는 세션이 나오면 또 터짐 — 근본 해결이
아닙니다). 그래서 맵-리듀스 방식으로 바꿨습니다: `Stop` 훅이 원문을
4,000자 안팎 쌓을 때마다 **그 조각만** 분류해서(이전 주제와 같은지
판단 후 이어붙이거나 새 해시태그 섹션을 엽니다) `waypoints/inprogress/<프로젝트>/<세션ID>.structured.md`
에 반영합니다. 이러면 세션이 아무리 길어도 한 번의 AI 호출이 봐야 하는
입력 크기는 항상 그 조각 하나로 유지됩니다. 세션 종료 시엔 마지막 남은
조각만 마저 분류하면 되므로, 이때도 큰 호출이 필요 없습니다. 이 구조화
임시본의 메타데이터(대표 태그, 파일명, 지금까지 소비한 원문 길이 등)는
헤더에 git-tracked로 같이 저장돼서, 세션이 죽은 뒤 **다른 세션**이
orphan 복구를 할 때도(로컬 state.json 없이) 이어서 처리할 수 있습니다.

**태그가 자꾸 다른 표기로 흩어지지 않게**
체크포인트가 새 해시태그를 지을 때, 그 프로젝트에서 이미 쓰인 태그
목록을 분류 프롬프트에 같이 줘서 재사용을 유도합니다 — 안 그러면
세션마다 `hooks`/`hook`/`Hooks`처럼 같은 개념이 다른 표기로 흩어져서
나중에 검색이 안 됩니다.

</details>

## 세션 종료 방법

| 환경 | 방법 |
|---|---|
| CLI | `exit` 입력 또는 `Ctrl+D` (`Ctrl+C` 강제 종료는 피하세요) |
| 웹(claude.ai/code) | 세션 목록에서 **Archive** — 단, 원문은 Archive 여부와 무관하게 이미 매 턴 저장되어 있습니다 |

## 기록 확인하기

- **전체 현황**: `waypoints/INDEX.md` — 프로젝트 → 대표 태그(상태) → `#해시태그` → 항목의 3단 트리
- **개별 기록**: `INDEX.md` 링크 → `waypoints/tags/...` 아래 `.md` — 요약, 결정 이유, 미탐색 대안까지
- **원문이 궁금하면**: 그 기록의 프론트매터 `raw:` 경로 → `waypoints/raw/...`에 원문 그대로 보관돼 있음 (요약이 놓쳤을 수도 있는 뉘앙스 확인용)
- **대화로 조회**: `/waypoint` 스킬 (아래 표)

| 입력 예시 | 결과 |
|---|---|
| `/waypoint` 또는 "지금까지 뭐 했어?" | 프로젝트 진행 상황 브리핑 |
| `/waypoint adr` 또는 "의사결정 기록으로 정리해줘" | ADR 문서 생성 |
| "이거 비슷한 거 예전에 겪지 않았어?" | 과거 유사 사례 검색 |
| "반복되는 패턴 있어?" | 재사용 가능한 프롬프트 템플릿 제안 |
| "이번 주 작업 리포트 보여줘" | 태그별 통계 요약 |

## 점검 체크리스트

아직 실사용 검증 전이라, 당분간 아래를 가끔 확인해보는 걸 권장합니다.

| 확인 대상 | 정상 상태 | 이상 신호 |
|---|---|---|
| `waypoints/.debug.log` | 파일 없음 | 있으면 훅 스크립트에서 에러 발생 (내용으로 단계 파악) |
| `waypoints/inprogress/` | 세션 종료+다음 세션 시작 후 비어있음 | 계속 파일이 남아있으면 `SessionEnd`/orphan 복구 아직 안 됨 (데이터는 안전, 분류만 지연) |
| `git log` | `waypoint-log:` 커밋들 뒤에 `waypoint: <프로젝트>/<제목>` 하나로 정리됨 | 패턴이 안 보이면 훅이 안 도는 것 |
| `INDEX.md`의 "미분류" 태그 | 거의 없음 | 자주 보이면 AI 분류 호출이 실패 중 (데이터는 안전) |
| `waypoints/` 커밋 위치 | `git log origin/master --oneline`에 보임 | 안 보이고 `.debug.log`에 "동기화 실패"가 있으면 폴백(세션 브랜치)으로 빠진 것 — PR 머지 필요 |

## 동작 원리

| 시점 | 훅 | 하는 일 |
|---|---|---|
| 세션 시작 | `SessionStart` | 이전 세션이 못 끝낸 원문(orphan)이 있으면 먼저 정리 |
| 매 턴 | `Stop` | 대화를 `waypoints/inprogress/<프로젝트>/<세션ID>.md`에 append + 기본 브랜치로 commit+push. 누적 원문이 임계값을 넘으면 그 조각만 체크포인트 분류해서 구조화 임시본(`.structured.md`)과 `INDEX.md`에도 반영 |
| 세션 종료 | `SessionEnd` | 마지막 남은 조각을 마저 체크포인트 분류 → 완성된 구조화 임시본을 `waypoints/tags/`에 최종 문서로 저장 → 원문은 `waypoints/raw/`로 옮겨서 보관(삭제 안 함) → `INDEX.md` 최종 상태 반영 → `inprogress/` 정리 → 기본 브랜치로 commit+push |

두 훅 모두 `lib_common.sync_waypoints_to_master()`를 통해 push합니다. 실패 시(네트워크 등) 세션 브랜치 직접 커밋으로 폴백해서 데이터 유실만은 항상 막습니다.

> 용어: "waypoint"는 Claude Code 기본 기능인 `/checkpoint`(파일 편집 되돌리기)와 무관합니다.

## 폴더 구조

```
waypoints/
  .tmp/                   # 세션 진행 오프셋만 (git 미포함)
  inprogress/<프로젝트>/<세션ID>.md              # 진행 중 원문 로그 (git-tracked)
  inprogress/<프로젝트>/<세션ID>.structured.md   # 체크포인트로 쌓이는 해시태그별 구조화 임시본
  tags/<프로젝트>/<대표태그>/<날짜-시간>-<제목>.md   # 분류 완료된 최종 요약 문서
  raw/<프로젝트>/<대표태그>/<날짜-시간>-<제목>.md    # 같은 이름의 원문 전체 (요약과 짝, 삭제 안 함)
  INDEX.md                # 태그트리 — 프로젝트 → 대표태그 → #해시태그 → 항목
```

## 다른 프로젝트에 설치하기

기록 위치는 `.claude/scripts/lib_common.py`가 **물리적으로 어디 있는지**로 정해집니다 (`PROJECT_ROOT` = 스크립트 위치에서 두 단계 위). 설치 방식에 따라 기록 범위가 달라지므로 먼저 선택하세요.

| | 방식 A: 프로젝트별 격리 (기본 권장) | 방식 B: 여러 프로젝트 중앙집중 |
|---|---|---|
| 설치 위치 | 각 프로젝트 저장소 안 | 별도 중앙 저장소 + Claude Code **사용자 전역 설정** |
| 기록 범위 | 그 프로젝트 안에서만 | 다루는 모든 프로젝트가 한 곳에 |
| 데자뷰 감지 | 프로젝트 경계 못 넘음 | 전체 이력 대상으로 동작 |
| 적합한 경우 | 회사/클라이언트별 접근 권한 분리 필요 | 개인이 여러 프로젝트 넘나들며 씀 |

**지금 이 저장소(`waypoint`)가 실제로 방식 B로 운영되고 있습니다** — 여러 프로젝트를 다루면서도 `waypoints/tags/<프로젝트>/` 형태로 프로젝트별 태그만 나눠서 한 저장소에 모아 기록합니다.

<details>
<summary><b>설치 절차 (자세히)</b></summary>

**방식 A**
1. `.claude/settings.json`, `.claude/scripts/`, `.claude/skills/waypoint/`를 그 프로젝트 저장소 안에 복사
2. 이미 `.claude/settings.json`이 있다면 `hooks` 항목만 병합 (덮어쓰지 말 것)
3. `python3`, `git`, `claude` CLI가 실행 가능해야 함
4. 각 프로젝트는 자기 저장소에만 커밋 — 서로의 기록을 못 봄

**방식 B**
1. 스크립트는 **중앙 저장소 하나에만** 설치하고 그대로 유지 (옮기면 `PROJECT_ROOT`가 바뀌어 기록 위치도 바뀜)
2. `.claude/settings.json`의 훅 설정을 프로젝트별이 아니라 **사용자 전역 설정**에 등록
3. 각 훅이 세션의 `cwd`에서 git remote 이름을 읽어 `waypoints/tags/<프로젝트>/...`로 나눠 저장

두 방식을 섞을 수도 있습니다 (일부 프로젝트만 A로 격리, 나머지는 B의 중앙 저장소로) — 단, 한 프로젝트 디렉터리에 두 방식의 훅이 동시에 걸리지 않게 주의하세요 (중복 커밋/충돌 원인).

여러 사람이 방식 B의 중앙 저장소를 같이 쓰는 경우, 서로 다른 사람의 작업 요약이 한 저장소에 다 보이게 된다는 점도 고려하세요.

</details>

## 알려진 한계

| 항목 | 내용 |
|---|---|
| `SessionEnd` 미실행 보장 없음 | idle 타임아웃 시 확실히 실행되는지 공식 문서에 없음. 다만 원문은 매 턴 이미 push돼 있어 **유실 위험은 없고 분류만 늦어짐** |
| 커밋 수 증가 | 대화가 길수록 `waypoint-log:` 커밋이 여러 개 쌓임 (세션 종료 시 최종 문서 하나로 정리는 되지만 히스토리엔 남음). 필요시 주기적 squash 고려 |
